Yarn stock tracker by count, dye-lot and shade for weaving units

A free, single-file tool that holds every yarn balance per dye-lot, allocates issues oldest lot first, and converts between Ne, Nm, tex, denier and folded counts without getting the reciprocal backwards. It runs on your own machine and sends nothing anywhere.

Weaving and knitting units, dyers and yarn traders Single binary, no database Mill-floor stock control

What it does

Yarn is not a fungible commodity, and most stock software treats it as though it were. Two lots of one nominal shade come out of separate dye baths, and the difference between them shows up as a visible colour band across the finished fabric at the point the warp or the feed changes over. A single pooled “30s Navy: 225 kg” balance hides exactly the information a weaver needs before cutting a warp.

This tool holds the balance per lot instead. The stock key is count, shade, dye-lot and supplier together — the supplier included because two spinners happily reuse the same lot numbers. On top of that it does the arithmetic a yarn store actually needs:

  • Balance per lot — receipts, less issues, plus or minus adjustments. An issue that would drive a lot negative is refused outright, naming the shortfall, because a negative balance means a slip or a receipt is wrong and both need a person.
  • FIFO allocation on issue — ask for 120 kg of 30s Navy and the tool spreads it across dye-lots oldest receipt first, shows you the per-lot allocation and how many shade joins it implies, and writes nothing until you confirm.
  • Count conversion — Ne, Nm, tex and denier in both directions, plus folded counts: 2/60s is read as a two-fold of 60s singles and resolves to a resultant Ne 30.
  • Consumption against standard — what a production run should have drawn against what was actually issued, as a variance and as a wastage percentage.
  • Reorder and aged-lot alerts — what has fallen below its reorder level with a suggested order quantity, and which lots have sat long enough to be a shade-drift risk.

Who it's for

Small and medium weaving and knitting units, commission dyers, and yarn traders in India and the Philippines — the shed with four to forty looms, or a circular knitting floor, where the yarn store is run from a notebook or a spreadsheet and the count conversions are done on a phone calculator. If a buyer has ever rejected a piece for a shade band, this tool is built for that problem.

It assumes someone on the floor can type a dye-lot number off a cone label. It does not assume an accountant, a server, or an internet connection.

The rule it implements

No statute applies to this tool, and it does not pretend one does. Yarn stock control is not a regulated return; it is a physical and arithmetic discipline. Rather than invent a compliance hook, here is precisely what the tool implements and the exact figures it uses.

The physical rule: dye-lot integrity. Stock is never pooled above the dye-lot. Issues consume one lot to exhaustion before opening the next, both because the oldest lot has had the longest to drift in storage and because it keeps the number of shade joins in a run to a minimum.

The conversion rules. Ne and Nm are indirect counts (length per unit mass: a bigger number is a finer yarn). Tex and denier are direct (mass per unit length: a bigger number is coarser). Converting between the two families is a reciprocal, not a multiplication. Tex is the hub, so there is exactly one path between any two systems:

tex    = 1000 / Nm         Nm     = 1000 / tex
Ne     = 590.5 / tex       tex    = 590.5 / Ne
denier = 9 x tex           tex    = denier / 9

A folded count divides in Ne and multiplies in tex, which is the same statement twice: a two-fold of 60s singles is a resultant Ne 30 and a resultant 19.683 tex, and 2/60s, 3/90s and 30s all resolve to the same resultant count.

The exact constants used, and where they come from

1000 (Nm ↔ tex) is exact by definition: Nm is metres per gram and tex is grams per 1000 metres.

9 (denier ↔ tex) is exact by definition: denier is grams per 9000 metres.

590.5 (Ne ↔ tex) is a rounding. Ne is the number of 840-yard hanks per pound, so the factor is 453.59237 g ÷ (840 × 0.9144 m) × 1000 = 590.5412474…. Mill practice everywhere rounds this to 590.5, and that is what this tool uses: every conversion is therefore within 0.007% of exact. That is far inside any commercial tolerance, but if your buyer's contract specifies a different factor, convert with theirs before quoting.

90 days is the default age past which a lot still holding stock is flagged for shade-drift risk. This is a common working figure, not a standard — drift depends on your fibre, dye class and godown conditions. Change it in the Alerts tab to whatever your own re-sampling experience says.

Twice the reorder level is the default order-up-to target when you have not set one. A reorder level is only a trigger, so ordering exactly the shortfall would put the item straight back on the alert list. Set an explicit order-up-to figure to match your supplier's lead time and minimum dye-lot size.

24 plies is the largest ply count accepted. Its real job is to catch the reversed notation: 60/2 means the same yarn as 2/60s in some trades, and reading it plies-first would silently take a count from 30 to 0.033, so it is refused with an explanation instead of guessed at.

All quantities are held internally as whole grams rather than as fractional kilograms. That is what lets an exact-fit issue empty a lot to precisely zero, and stops a long run of receipts and issues drifting by a fraction of a gram into a false negative balance.

Install & run

You need Go 1.25 or later once, to build it (from go.dev/dl). After that it is a single executable you can copy to any machine of the same kind — no runtime, no database, no installer.

git clone https://github.com/sreenivas-sadhu-prabhakara/yarn-inventory-count-lot
cd yarn-inventory-count-lot

# build the binary
go build -o yarn-inventory-count-lot .
./yarn-inventory-count-lot

# or just run it from source
go run .

Then open http://127.0.0.1:8080 in a browser on the same machine. Two flags change the defaults:

./yarn-inventory-count-lot -addr 127.0.0.1:9000 -data /path/to/yarn-book.json
  1. Book your opening stock in on the Receive tab, one dye-lot at a time, or import it all at once from a CSV on the Data tab.
  2. Set a reorder level for the counts and shades you keep in stock, on the Alerts tab.
  3. From then on, raise every production issue on the Issue tab by count and shade. Check the lot allocation it proposes, then confirm it.
  4. Export the balance sheet and the issue register to CSV whenever your accountant or your buyer asks.

What it stores

One JSON file on your own machine — ./yarn-inventory-count-lot-data.json by default, or wherever -data points. It holds your movements, your reorder levels and your aged-lot threshold, and nothing else.

The file is written atomically: the tool writes a temporary file alongside it, flushes it, and renames it over the target, so a power cut during a save leaves your previous file intact rather than a truncated one. It is written with owner-only permissions. Because it is plain JSON, you can read it, diff it, put it in version control, or back it up by copying it.

The tool binds to 127.0.0.1, the loopback interface, so nothing outside your machine can reach it unless you deliberately change -addr. It makes no outbound network calls of any kind: no telemetry, no analytics, no update check, no fonts or scripts from a CDN. The web interface is compiled into the executable. You can run the whole thing on an air-gapped machine and nothing will be missing.

Features

Balance per dye-lot

Receipts less issues, plus or minus adjustments, held against count, shade, dye-lot and supplier together. Capitalisation and stray spacing are ignored, so one physical lot never splits into two balances.

FIFO lot allocation

Issue by count and shade; the tool spreads it across lots oldest receipt first and shows you each line, what is left after, and how many shade joins the run will carry, before anything is written.

Never goes negative

An issue or a write-off bigger than the stock is refused, with the shortfall named in kilograms. Partly-filled allocations are never written: either the whole issue posts or none of it does.

Count conversion panel

Ne, Nm, tex and denier in every direction, plus folded counts like 2/60s with the singles tex alongside the resultant. Malformed and reversed count strings are rejected rather than guessed.

Consumption variance

Standard requirement against yarn actually issued over a date range, reported both as a percentage of standard and as the conventional mill wastage percentage on issue.

Reorder alerts

What has fallen to or below its reorder level, with a suggested order quantity. Items that have run out completely still appear, instead of silently vanishing from the list.

Aged-lot warnings

Lots still holding stock past a threshold you set, oldest first, so an old part-lot gets cleared or re-sampled before it goes into a long run next to a fresh lot.

CSV in and out

Import receipts from your existing sheet — columns matched by name, in any order, with common alternatives understood. Export balances by lot and the full issue register.

Traceable issue register

Every issue records which dye-lot each kilogram came off, against its work order. That is the record a shade complaint from a buyer gets answered with.

Scope and honesty. This is a stock and conversion tool, not an accounting package, an ERP, or a costing system. It does not value your stock, post to a general ledger, handle GST or VAT, manage purchase orders, or track work in progress. It has no multi-user support and no access control: anyone who can use your machine can use it.

The conversion constants are definitional and are stated exactly above. The 90-day aged-lot default and the order-up-to multiple are working judgements, not standards, and you should set both from your own fibre, storage and lead-time experience. The variance figures are only as good as the grams-per-unit standard you type in. Nothing here is a substitute for sampling a shade against the lot you are about to run.
